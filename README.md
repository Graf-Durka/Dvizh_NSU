# «Движ НГУ» — Платформа студенческих возможностей и набора участников

Веб-сервис для Новосибирского государственного университета (НГУ), позволяющий лабораториям, студенческим объединениям и организаторам публиковать научные проекты, волонтёрские роли и разовые задачи с прозрачными условиями (нагрузка в часах, дедлайн, вознаграждение), а студентам — находить подходящее участие и отслеживать статус заявок.

Разработано в точном соответствии с бизнес-гипотезой (Lean Canvas) и Техническим заданием (ТЗ).

## 🌟 Ключевые возможности (Функции MVP)

### F1. Публикация возможностей и первичная модерация
- **Форма создания роли:** название, категория (*Научный проект*, *Волонтёрская роль*, *Разовая задача*), обязанности (до 2000 симв.), локация, нагрузка (0.5–400 ч.), число мест (1–500), даты начала/окончания и дедлайн, виды поощрения (*Опыт*, *Мерч*, *Питание*, *Билет*, *Вознаграждение* или *Без вознаграждения*) и конкретные условия выдачи.
- **Первичная модерация:** первая карточка нового организатора отправляется модератору НГУ (`PENDING_REVIEW`). Одобрение модератором одновременно подтверждает автора (`verified = True`), после чего все последующие карточки публикуются в каталоге сразу.
- **Защита условий участия:** после появления первого отклика условия роли блокируются от изменений (название, даты, обязанности, вознаграждение). Организатор может только увеличить число мест.
- **Управление набором:** возможность отозвать карточку с проверки в черновик, а также закрыть набор (`CLOSED`), удалив его из активного каталога.

### F2. Каталог и многофакторный поиск
- **Открытый доступ:** каталог и полные карточки доступны без регистрации.
- **4 независимых фильтра (объединяются по «И»):**
  1. *Категория* (научный проект, волонтёрская роль, разовая задача);
  2. *Диапазон дат начала* (с даты по дату по времени Новосибирска);
  3. *Нагрузка* (дискретные интервалы: $\le 2$ ч., от $2$ до $4$ ч., $> 4$ ч.);
  4. *Вид поощрения* (опыт, мерч, питание, билет, деньги, без вознаграждения).
- **Индикация мест:** при заполнении всех мест карточка остаётся в каталоге до дедлайна с ярким бейджем **«Мест нет»**, а кнопка отклика блокируется.
- **Пагинация:** 12 карточек на страницу.

### F3. Отклик, транзакционный учёт мест и завершение цикла
- **Подача отклика:** студент отправляет краткий комментарий (до 500 симв.). Повторный отклик на ту же роль запрещён на уровне БД (`UNIQUE(opportunity, student)`).
- **Принятие без бронирования:** организатор принимает заявку (`ACCEPTED`). Принятие **не занимает место**, что позволяет организатору одобрить пул кандидатов с запасом.
- **Транзакционное подтверждение места:** студент подтверждает участие (`CONFIRMED`). Внутри транзакции с блокировкой строки в БД (`select_for_update`) проверяется лимит мест. Если места исчерпаны, выдаётся понятный экран **409 Conflict**, а заявка остаётся принятой.
- **Освобождение места при отмене:** до начала события студент может отменить подтверждение (`CANCELLED`), при этом место мгновенно освобождается в системе для других кандидатов (в том числе после закрытия набора).
- **Фиксация выполнения:** после закрытия набора и окончания события организатор отмечает выполнение роли (`COMPLETED`).
- **Аудит и история:** каждый переход статуса сохраняется в неизменяемом журнале `ApplicationEvent` с фиксацией времени и инициатора изменения.

## 🛠 Технологический стек

- **Бэкенд:** Python 3.11, Django 5.2 (серверные шаблоны, `select_for_update`, CSRF-защита, штатные хеши паролей PBKDF2).
- **База данных:** SQLite (для локального запуска из коробки) / PostgreSQL (полная поддержка через переменные окружения).
- **Фронтенд:** Адаптивная вёрстка (Bootstrap 5, Bootstrap Icons, фирменная палитра НГУ), полная поддержка экранов смартфонов от 360 px.
- **Часовой пояс:** `Asia/Novosibirsk` (UTC в базе данных).
